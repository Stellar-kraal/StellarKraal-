# How to Add a CHANGELOG Entry

`CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and is
kept under the `[Unreleased]` heading until `release-please` cuts a version.

## Where to add your entry

Add a bullet under the matching subsection of `## [Unreleased]`:

- `### Added` — new features
- `### Changed` — changes to existing behavior
- `### Deprecated` — soon-to-be removed features
- `### Removed` — removed features
- `### Fixed` — bug fixes
- `### Security` — vulnerability fixes

Create the subsection heading if it doesn't exist yet.

## Entry format

```
- Short, user-facing description of the change (#PR_NUMBER)
```

- Start with a capital letter, no trailing period.
- Describe the user-visible effect, not the implementation.
- Always reference the PR number in parentheses.

Example:

```
### Added
- Partial repayment support for active loans (#142)
```

## Notes

- Do not hand-edit the version headers (e.g. `## [1.4.0]`) — those are generated by the
  `release-please` workflow from Conventional Commits (see `CONTRIBUTING.md`).
- One bullet per PR/change is preferred over batching multiple changes into one line.
